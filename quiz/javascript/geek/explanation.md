# 解説

GEEKという文字列を変換するようです。

```javascript
[_='GEEK'.small()[2]]+[-~_._|2];
```

`small()`メソッドは、文字列を `<small>` タグで囲みます。

```javascript
> 'GEEK'.small():
'<small>GEEK</small>'
```

`<small>GEEK</small>`のインデックス2の文字は`m`です。

```javascript
> 'GEEK'.small()[2]:
'm'
```

`[_='GEEK'.small()[2]]`の部分で、変数`_`に文字列`m`が代入されていることがわかります。
角括弧`[]`は配列リテラルです。結果は`['m']`という配列になります。
前半部分を簡略化すると以下のような式になります。

```javascript
[_ = 'm']
```

問題後半を見てみます。

```javascript
[-~_._|2]:
```

`_._`は文字列`s`のプロパティ`_`にアクセスしようとします。
しかし、これは存在しないため、`undefined`と評価されます。

`~_._`は実質的に `~undefined` と等価になります。
ビット否定演算子`~`はオペランドを32ビット符号付き整数に変換します。
内部的には`undefined`は数値の`NaN`に変換され、`NaN`はビット演算では`0`に変換されます。
したがって、`~undefined`は`~0`であり、結果は`-1`です。

つまりアンダーバーの部分は`-(-1)`であり、`1`となります。
```javascript
> -~_._
> -(-1)
1
```

`[1 | 2]`では、ビット論理和演算子`|`を実行します。

- 1の二進数表現は01。
- 2の二進数表現は10。
- 01|10は11であり十進数では3

上記より、`[-~_._|2]` は `3` となります。

問題に戻ると、２つの配列を加算している式である事が見えてきます。

```javascript
['m'] + [3]
```

`+`演算子は、オペランドの少なくとも一方が文字列である場合、文字列連結として機能します。
配列の場合、`toString()`メソッドが呼び出され、コンマ区切りの文字列に変換されます。
つまり`['m']+[3]`は`'m'+'3'`と同じです

```javascript
> [_='GEEK'.small()[2]]+[-~_._|2]
'm3'
```

ギークな問題の答えはM3でした！
