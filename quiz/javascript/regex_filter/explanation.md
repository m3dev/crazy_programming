# 解説

```sh
node -e 'console.log((r => ["3M", "M3"].filter(s => r.test(s)))(/[0-9]+/g))'
node -e 'console.log((r => ["M3", "3M"].filter(s => r.test(s)))(/[0-9]+/g))'
```

このクイズで、なぜ配列の順番だけで結果が変わるのかを解説します。

---

## 全体の構造

どちらも、1つの正規表現 `r` を使って配列を `filter` しています。

```javascript
(r => [...].filter(s => r.test(s)))(/[0-9]+/g)
```

ポイントは正規表現に付いている **グローバルフラグ `g`** です。

---

## 1. `g` フラグ付き正規表現は `lastIndex` を保持する

`g` フラグの付いた正規表現は、`test()` を呼ぶたびに内部の `lastIndex` プロパティを更新し、**次回の検索開始位置を覚えています**。

* マッチ成功 → `lastIndex` がマッチ末尾の位置に進む
* マッチ失敗 → `lastIndex` が `0` にリセットされる

`filter` のように同じ正規表現を使い回すと、この状態が悪さをします。

---

## 2. `["3M", "M3"]` の場合 → 両方残る

```javascript
> (r => ["3M", "M3"].filter(s => r.test(s)))(/[0-9]+/g)
[ '3M', 'M3' ]
```

* `r.test("3M")`：先頭（index 0）の `'3'` にマッチ → `true`。`lastIndex` は `1` に進む
* `r.test("M3")`：`lastIndex = 1` から探す。`'3'`（index 1）にマッチ → `true`

両方とも `true` なので、配列はそのまま `["3M", "M3"]` が残ります。

---

## 3. `["M3", "3M"]` の場合 → 片方だけ残る

```javascript
> (r => ["M3", "3M"].filter(s => r.test(s)))(/[0-9]+/g)
[ 'M3' ]
```

* `r.test("M3")`：`'3'`（index 1）にマッチ → `true`。`lastIndex` は `2` に進む
* `r.test("3M")`：`lastIndex = 2` から探すが、`"3M"` は長さ2なので index 2 は範囲外 → マッチせず `false`。`lastIndex` は `0` にリセットされる

`"3M"` 自体には数字 `'3'` が含まれているのに、検索開始位置が後ろにずれていたせいで見逃され、`"M3"` だけが残ります。

---

## まとめ

1. `g` フラグ付き正規表現は `test()` 呼び出し間で `lastIndex`（検索開始位置）を保持する
2. `filter` で同じ正規表現を使い回すと、前の要素の状態が次の要素に影響する
3. その結果、まったく同じ要素の集合でも **並び順** で結果が変わる
4. 状態を持つ正規表現を使い回さないことが教訓
