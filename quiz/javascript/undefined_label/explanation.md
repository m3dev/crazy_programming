# 解説

```sh
node -e "console.log(eval(\"{undefined:[1]}['undefined'][0]\"))"
```

このクイズがなぜ `undefined`（文字列）を出力するのか、ステップごとに解説します。

---

## 全体の構造

`eval` に渡している文字列はこれです。

```javascript
{undefined:[1]}['undefined'][0]
```

一見すると、

```javascript
{ undefined: [1] }   // オブジェクトリテラル？
```

のようにオブジェクトを作り、そこから `['undefined'][0]` でプロパティを取り出しているように見えます。
しかし実際にはそうではありません。

---

## 1. 先頭の `{}` はブロック文

JavaScript では、文の先頭に現れる `{` は **オブジェクトリテラルではなくブロック文** として解釈されます。

```javascript
{ undefined: [1] }
```

つまりこれは「ブロック」であり、その中身は次のように読まれます。

* `undefined:` … **ラベル文**（`undefined` という名前のラベル）
* `[1]` … ラベルが付いた **式文**（配列リテラル `[1]`）

オブジェクトのキーと値ではありません。
このブロック文は値としては何も外に返しません。

---

## 2. 残りは別の式

ブロック文が終わったあとに、続けて次の式が評価されます。

```javascript
['undefined'][0]
```

* `['undefined']` は要素が1つの配列（中身は文字列 `'undefined'`）
* `[0]` でその0番目を取り出す

したがって、この式の値は文字列の `'undefined'` です。

```javascript
> ['undefined'][0]
'undefined'
```

---

## 3. `eval` は最後の式の値を返す

`eval` は、与えられた文字列を実行し、**最後に評価された式の値** を返します。

* 先頭のブロック文は値を持たない
* 最後の式 `['undefined'][0]` の値は文字列 `'undefined'`

そのため `eval(...)` 全体の値は文字列の `'undefined'` になります。

```javascript
> eval("{undefined:[1]}['undefined'][0]")
'undefined'
```

これを `console.log` すると、画面には

```text
undefined
```

と表示されます。`undefined` という値ではなく、`"undefined"` という文字列が出ているのがポイントです。

---

## まとめ

1. 文の先頭の `{...}` はオブジェクトではなく **ブロック文**
2. `undefined:` は **ラベル**、`[1]` はラベル付きの式
3. 続く `['undefined'][0]` が別の式として評価され、文字列 `'undefined'` になる
4. `eval` は最後の式の値を返すため、結果は文字列 `'undefined'`
