# 解説

```sh
node -e 'console.log(parseInt`256${~-16}`.toString`24`)'
```

このクイズがなぜ `m3` を出力するのか、ステップごとに解説します。

---

## 0. タグ付きテンプレートとは

`` 関数`...` `` という書き方は **タグ付きテンプレート** で、関数呼び出しになります。

```javascript
fn`a${x}b`
// ↓ とほぼ同じ
fn(["a", "b"], x)
```

* 第1引数：テンプレートの文字列部分の配列
* 第2引数以降：`${...}` の補間値

`parseInt` や `toString` はこの呼ばれ方を想定していないので、配列がそのまま渡って妙な挙動になります。

---

## 1. `~-16` を求める

```javascript
> -16        // -16
> ~(-16)     // 15  （~x === -(x+1) なので ~(-16) = 15）
```

`~-16` は `15` です。

---

## 2. `parseInt`256${~-16}`` を解釈する

タグ付きテンプレートなので、

```javascript
parseInt(["256", ""], 15)
```

という呼び出しになります。

`parseInt(string, radix)` の第1引数は文字列化されます。配列 `["256", ""]` を文字列化すると、要素をカンマで結合して `"256,"` になります。

```javascript
> parseInt("256,", 15)
531
```

`parseInt` は解釈できない文字（ここではカンマ）以降を無視するので、基数15で `"256"` を解釈します。

```text
2 × 15² + 5 × 15 + 6 = 450 + 75 + 6 = 531
```

よって `531` です。

---

## 3. `.toString`24`` を解釈する

得られた数値 `531` に対し、これもタグ付きテンプレートで `toString` を呼びます。

```javascript
(531).toString(["24"])
```

`Number.prototype.toString(radix)` の `radix` は数値へ変換されます。配列 `["24"]` を数値化すると `24` です。

```javascript
> Number(["24"])
24
```

つまり「531を24進数で表記」します。

```text
531 = 22 × 24 + 3
```

24進数では桁の値が `0-9` の次に `a, b, ...` と続きます。`22` は `'m'`（a=10, b=11, ... m=22）、`3` は `'3'` です。

```javascript
> (531).toString(24)
'm3'
```

よって出力は

```text
m3
```

となります。

---

## まとめ

1. `` parseInt`256${~-16}` `` はタグ付きテンプレートで `parseInt(["256",""], 15)`、基数15で `531`
2. `` .toString`24` `` は `(531).toString(24)`、24進数表記
3. `531 = 22×24 + 3` で、22→`'m'`、3→`'3'` なので `"m3"`
