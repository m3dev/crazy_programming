# 解説

```ruby
a=a|a=a
```

このコードの実行結果は `false` です。

## ポイント

`a` への代入が複数あり、未定義のはずの `a` を参照しているように見えますが、エラーにはなりません。

### 構文の区切り

代入 `=` は優先順位が低く右結合なので、この式は次のように解釈されます。

```ruby
a = (a | (a = a))
```

### ローカル変数は「解析時」に定義される

Rubyのローカル変数は、**代入式をパースした時点で定義済み**として扱われます。値が実際に入るのは実行時ですが、未代入の状態で参照すると例外ではなく `nil` になります。

この式にはあちこちに `a = ...` があるため、パーサは式全体を通じて `a` をローカル変数だと認識します。よって、まだ値が入っていない `a` を参照しても `NameError` にはならず `nil` が読み出されます。

### 評価

```ruby
a = (a | (a = a))
#         ^^^^^   最内: a = a … 右辺 a は nil なので a に nil を代入、式の値は nil
#     ^^^^^^^^^^^ nil | nil
```

`nil | nil` は `NilClass#|` の呼び出しで、右オペランドが偽（`nil`）なので `false` を返します。最後にその `false` が外側の `a` に代入され、式全体の値も `false` になります。

```ruby
a=a|a=a   # => false
```

「ローカル変数は解析時に定義され、未代入なら `nil`」というRubyの仕様と、`|` の論理演算メソッドを組み合わせた問題でした。
