# 解説

```ruby
!!?[??]
```

このコードの実行結果は **`SyntaxError`** です。

```
syntax error, unexpected end-of-input, expecting ':'
```

## ポイント

`?` から始まる文字リテラルと、三項演算子の `?` が衝突して構文エラーになります。

### `??` と `?[` の罠

Rubyの `?x` 記法は「`?` の直後の1文字」を文字リテラルにします。しかし `!!?[??]` のように記号が密集すると、パーサは `?` を **三項演算子（`条件 ? 真 : 偽`）の始まり** とも解釈しようとします。

ここでは `!!` による二重否定のあとに現れる `?` を、パーサが三項演算子の `?` として読み始めてしまいます。三項演算子には対応する `:` が必要ですが、式の末尾まで読んでも `:` が見つからないため、

```
unexpected end-of-input, expecting ':'
```

という「`:` を期待していたのに入力が終わった」という構文エラーになります。

### 既出問題との対比

よく似た見た目の問題に、RubyWorldConference2022 Day1-1 の `!??[??]` があります。こちらは先頭が `!??` なので `! (?? ... )` のように文字リテラル `??`（= `"?"`）として解釈が成立し、エラーになりません。

一方本問の `!!?[??]` は `!` がもう1つ多く、`?` が三項演算子側に倒れてしまうため、わずか1文字の違いでパース結果が大きく変わり、構文エラーになります。

`?` が「文字リテラル」と「三項演算子」のどちらに解釈されるかという、Rubyのレキサ／パーサの曖昧さを突いた問題でした。
