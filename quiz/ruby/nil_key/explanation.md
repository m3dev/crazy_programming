# 解説

```ruby
{nil:1}[nil]
```

このコードの実行結果は `nil` です。

## ポイント

一見すると「`nil` というキーに `1` を入れたハッシュから `nil` を引いているので `1` が返る」と読みたくなりますが、そうはなりません。

### `{nil:1}` の正体

`nil:1` は `nil: 1` と同じで、これは **シンボルをキーにしたハッシュリテラル** の記法です。`キー名: 値` という形は `:キー名 => 値` の糖衣構文なので、

```ruby
{nil:1}  # => {:nil=>1}
```

となります。つまりキーは `NilClass` の `nil` ではなく、**シンボル `:nil`** です。

### `[nil]` の参照

続く `[nil]` は、キーに `nil`（`NilClass` のインスタンス）を指定したハッシュ参照です。ハッシュが持っているキーは `:nil`（シンボル）であって `nil`（NilClass）ではないため、両者は別物として扱われ、対応する値は見つかりません。

存在しないキーを参照したときのデフォルト値は `nil` なので、最終的な結果は `nil` になります。

```ruby
{nil:1}        # => {:nil=>1}
{nil:1}[:nil]  # => 1     （シンボルで引けば取れる）
{nil:1}[nil]   # => nil   （NilClass の nil では引けない）
```

`シンボルキー記法` と `本物の nil` を取り違えさせる問題でした。
