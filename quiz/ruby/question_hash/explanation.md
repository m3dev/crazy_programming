# 解説

```ruby
{?}=>?{}[{}]
```

このコードの実行結果は `nil` です。

## ポイント

ここでも `?x` の文字リテラルが鍵です。

### `?}` と `?{` は文字リテラル

`?}` は文字列 `"}"`、`?{` は文字列 `"{"` です。`?` の直後の1文字が、たとえそれが波括弧であっても、文字リテラルとして取り込まれます。

### ハッシュ部分の解釈

これを踏まえると、先頭部分は次のように読めます。

```ruby
{ ?} => ?{ }
# = { "}" => "{" }
```

つまりキー `"}"`、値 `"{"` を持つハッシュ `{"}"=>"{"}` です。波括弧が文字リテラルに吸われるので、外側の `{ ... }` がきちんとハッシュリテラルとして閉じます。

### 末尾の `[{}]`

そのハッシュに対して `[{}]` で参照します。`{}`（空ハッシュ）をキーとして引いていますが、ハッシュが持つキーは `"}"` だけなので一致するものはありません。

存在しないキーの参照結果は `nil` なので、最終結果は `nil` になります。

```ruby
{?}=>?{}        # => {"}"=>"{"}
{?}=>?{}[{}]    # => nil
```

`?{` `?}` という、見た目が紛らわしい文字リテラルを見抜けるかを問う問題でした。
