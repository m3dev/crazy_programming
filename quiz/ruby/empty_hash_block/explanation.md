# 解説

```ruby
{}[{}]{}
```

このコードの実行結果は `nil` です。

## ポイント

`{}` が3つ並んでいますが、それぞれ役割が違います。

### 先頭の `{}` は空ハッシュ

式の先頭に来る `{}` は空のハッシュリテラルです。

### `[{}]` は参照

続く `[...]` は `Hash#[]`（要素参照）の呼び出しです。中身の `{}` はキーとして渡される空ハッシュです。

```ruby
{}[{}]
# 空ハッシュに対して、キー {} で参照
```

空ハッシュには何も入っていないので、どんなキーで引いても一致せず、結果は `nil` です。

### 末尾の `{}` はブロック

最後の `{}` は、直前の `[]` メソッド呼び出しに付いた **ブロック** として解釈されます。`Hash#[]` はブロックを取らないので、このブロックは単に無視されます（エラーにもなりません）。

```ruby
{}[{}]{}
# = ({}).[]( {} ) { }
#   ^^空ハッシュ  ^^キー ^^無視されるブロック
```

### 結果

参照結果がそのまま式の値になるので、最終結果は `nil` です。

```ruby
{}[{}]{}   # => nil
```

同じ `{}` という見た目が「ハッシュリテラル」「キー」「ブロック」と文脈によって異なる意味になることを問う問題でした。
