# 解説

```ruby
{}.tap{|h|h[1]=1}[1]
```

このコードの実行結果は `1` です。

## ポイント

記号が詰まっていて読みにくいですが、順を追えば素直な式です。

### `{}` は空ハッシュ

先頭の `{}` は、ここでは空のハッシュリテラルです（式の先頭なのでブロックにはなりません）。

### `.tap{|h| h[1]=1}`

`Object#tap` は、レシーバ自身をブロック引数に渡してブロックを実行し、**ブロックの戻り値に関係なくレシーバ自身を返す** メソッドです。

ここでは空ハッシュ `{}` が `h` に渡され、ブロック内で `h[1] = 1` が実行されます。これによりハッシュは `{1=>1}` になります。そして `tap` はそのハッシュ自身を返します。

```ruby
{}.tap{|h|h[1]=1}   # => {1=>1}
```

### 末尾の `[1]`

`tap` が返したハッシュ `{1=>1}` に対して `[1]` でキー `1` を参照します。値は `1` なので、最終結果は `1` になります。

`tap` が「副作用を起こしつつレシーバを返す」性質を使って、メソッドチェーンの途中で要素を仕込み、そのまま参照する流れを追わせる問題でした。
