# 解説

```ruby
p {nil: 1}
```

このコードの実行結果は **`SyntaxError`** です。

```
syntax error, unexpected ':', expecting '}'
```

## ポイント

`{:nil=>1}` が出力されることを期待したくなりますが、構文エラーになります。

### `{...}` はハッシュではなくブロック

メソッド呼び出しで引数を括弧で囲まずに `{...}` を続けて書くと、Rubyはその `{...}` を **ハッシュ引数ではなくブロック** として解釈します。

```ruby
p {nil: 1}
#  ^^^^^^^^ これは p に渡すブロック
```

ブロックとして解釈された `{...}` の中身は、ハッシュリテラルではなく **ブロック本体（式の並び）** として読まれます。そこに書かれている `nil: 1` という「シンボルキー記法」は、ハッシュリテラルの内側でしか意味を持たない文法なので、ブロック本体の式としては成立せず、`:` の位置で構文エラーになります。

### 括弧を付ければハッシュになる

`{...}` をハッシュとして渡したい場合は、メソッド呼び出しの括弧を明示します。

```ruby
p({nil: 1})  # => {:nil=>1} が出力される
```

括弧を付けることで `{...}` が「引数の一部（ハッシュリテラル）」と確定し、ブロック解釈されなくなります。

括弧を省略したときの `{}` の曖昧さ（ブロックか、ハッシュか）を突いた問題でした。
